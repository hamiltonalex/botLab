## Главная проблема, ради которой нужна новая сессия

За 72 часа условия входа сошлись **три раза**, и завершилась **одна** сделка. Проверять доходность
не на чем. Все прежние цифры вроде «75% прибыльных» были артефактом: получасовой кулдаун считал один
и тот же вход девять раз.

Арифметика: цикл сделки это удержание около 15 часов плюс кулдаун, условия входа сходились примерно
раз в сутки. Десять последовательных независимых сделок потребовали бы около 10 суток записи.

## Задача

Получить **не менее десяти завершённых сделок** за разумное время и оценить их результат. Счёт
бумажный, реальные ордера не выставляются нигде, терять нечего - это испытательный стенд.

Ключевая идея, которую надо проработать: **вести несколько позиций параллельно**, а не одну за
другой. Сейчас `maxConcurrent` равен 2 и фактически не используется. N одновременных позиций на
разных инструментах дают N-кратное число сделок за то же время, не трогая издержки.

Что нужно продумать и проверить по записи (`npm run eval:buy` и соседние инструменты читают её
офлайн, ничего не запуская):

1. **Параллельные позиции.** Сколько одновременно, на каких инструментах, как не набрать N позиций в
   один и тот же риск. Сейчас все входы шли в один инструмент подряд - это не диверсификация.
2. **Пороги входа.** Понизить или пересмотреть принципы. Порог запаса недооценки 3 пункта даёт
   16.8% времени, 2 пункта - 29.6%, 1 пункт - 53.3%. Ослабление порогов ухудшает качество каждой
   сделки, но даёт объём для проверки. Найди разумный баланс и обоснуй его числом.
3. **Гибкая логика внутри открытой сделки.** Сейчас выходы статичны: тейк, стоп, тайм-стоп. Диагностика
   показала, что максимум прибыли наступает через 20.8 часа медианой, а тайм-стоп в 12 часов резал
   позиции прямо перед разворотом. Продумай что-то адаптивное: трейлинг, частичную фиксацию,
   пересмотр по изменению волатильности. Цель - чтобы сумма сессий не сходилась в большой минус.
4. **Длительность следующей обкатки.** Посчитай, сколько нужно, с учётом выбранных параллельности и
   порогов.

## Законы проекта, которые нельзя нарушать

- **Пороги живут только в пресетах** (`src/engine/otmscan/presets.js`), никогда в коде условий.
- **Движок PURE**: без сети, файлов, DOM и `Date.now()`. Время приходит аргументом.
- **Три состояния условия**: прошло, не прошло, данных нет. «Данных нет» блокирует вход и отличимо
  от «не прошло». Никогда не превращай отсутствие данных в ноль или в отказ.
- **Ордера не выставляются нигде.** Всё бумажное, только публичное чтение Deribit.
- Каждая правка - отдельный коммит, `npm test` после каждой, плюс `npm run oracle` и `npm run e2e:ui`
  при изменениях интерфейса.

## Грабли, на которых прошлая сессия уже стояла

- `entries.map(runTrade)` передаёт колбэку **индекс** вторым аргументом. Когда во второй параметр
  добавили тайм-стоп, сделки стали закрываться через N часов по номеру в массиве. Ошибка была видна
  в списке сделок и всё равно прожила несколько прогонов.
- **Кулдаун превращает одну идею в много строк отчёта.** Проверяй, сколько РАЗНЫХ инструментов в
  выборке, прежде чем считать долю прибыльных.
- **Квантили по всей выборке дают фору.** На тех же данных схема со скользящим суточным окном даёт
  вдвое меньше входов, чем схема с квантилями по всей истории.
- **Разность медиан обманывает.** Медианы RV 25.46 и IV 27.67 читаются как «IV выше RV», хотя парно
  RV выше IV в 75% замеров. Считай парные величины.
- **Пресет заморожен** `deepFreeze`, мутировать его поля нельзя - передавай параметры явно.
- Сканер не тикает без показа своей вкладки; для многосуточных прогонов есть `SCN_AUTOSTART=1`.

## Как работать

Сначала разберись в артефактах и посчитай по имеющейся записи, потом предлагай изменения кода.
Запись самодостаточна: любой набор порогов и правил проверяется по ней за минуты. Новую обкатку
запускай только когда офлайн-расчёт покажет, что она даст нужное число сделок.

Машина для обкаток: `192.168.86.214` (не по имени, оно резолвится ненадёжно), ключ
`~/.ssh/botlab_soak`, Node 22 в `/usr/local/bin` (экспортировать PATH в каждой SSH-команде).
