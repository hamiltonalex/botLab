# Марковская модель 1D: скрипты Дмитрия и стенд проверки

## Что это

Идея заказчика (сентябрь 2026): дневные свечи Binance, пять состояний дня по квинтилям доходности
close/open за последние 200 дней, матрица переходов между состояниями, сигнал LONG или SHORT на завтра
по тому, какие состояния чаще следовали за сегодняшним, стоп на экстремуме вчерашней свечи, выход по
закрытию. «Адаптивная» версия перебирает 31 подмножество состояний и берёт то, у которого выше оценка
equity / (1 + сделок / 100), то есть прибыль со штрафом за число сделок, на тех же 200 днях. Описание идеи словами заказчика лежит в `original/dmitri_new_idea.rtf`.

## Откуда файлы

- `original/`: три файла, как получены от Дмитрия 2026-09-10, байт в байт. Не править никогда.
- `markov_adaptive_bot_binance_v2.py`, `hyperliquid_markov_bot_v2.py`: рабочие копии тех же скриптов.
  В них по одному коммиту на дефект исправлен только учёт (стоп по минимуму и максимуму дня, незавершённая
  свеча, обучение только по прошлому, комиссия и проскальзывание, протухшие данные; по аудиту 13.09: перекачка
  истории после закрытия нового дня, последняя закрытая пара в оценке, неполные дни и пропуски не торгуются);
  сама стратегия (состояния, матрица переходов, выбор сигнала, перебор комбинаций) не меняется, меняются данные,
  учёт сделок и способ проверки. Это версия, которую можно вернуть заказчику.
- `markov_walkforward.py`: стенд-арбитр на чистом Python (без numpy). Загружает два модуля, оригинал из
  `original/` (столбец «как получено») и рабочую копию (столбец «исправлено»), гоняет оба на одном кэше
  свечей и печатает рядом со своей независимой опорой: та же процедура отбора комбинации, но развёрнутая
  во времени (квантили, матрица и комбинация только по окну до сделки), с режимом стопа (`--mode asis`
  как в коде, `--mode intraday` по минимуму и максимуму дня) и комиссией (`--fee`, `--slip`) как параметрами,
  которые применяются и при отборе внутри окна, и на сделке. Проверяет, что правки не тронули стратегию
  (состояния, матрица и решения оригинала и рабочей копии совпадают), считает цену «пола» стопа по закрытию
  (всегда лонг и монетка через `backtest()` каждого модуля), плацебо на перемешанных свечах, купил и держи,
  и сверяет `walk_forward()` рабочей копии со своей опорой до четвёртого знака.
- `markov_baselines.py`, `markov_deepdive.py`: вспомогательные разборы к стенду (базовые линии по годам,
  направления, монетки в те же дни).
- `requests_stub.py`: замена пакета `requests` поверх стандартной библиотеки, чтобы скрипты и стенд
  запускались без установки пакетов.

## Как запускать

Нужен Python 3. Если пакета `requests` нет, один раз подложить заглушку:

    mkdir -p stub && cp requests_stub.py stub/requests.py

Исправленная рабочая копия (печатает честные числа по восьми монетам; оригинал в `original/` запускается так же):

    PYTHONPATH=./stub python3 markov_adaptive_bot_binance_v2.py

Стенд (первый запуск качает всю дневную историю Binance в `klines-cache/`, дальше берёт из кэша шесть часов):

    PYTHONPATH=./stub python3 markov_walkforward.py --mode asis --fee 0        # учёт как получено: базовая линия
    PYTHONPATH=./stub python3 markov_walkforward.py --mode intraday --fee 0    # стоп по дню, без комиссии
    PYTHONPATH=./stub python3 markov_walkforward.py --mode intraday --fee 0.001 --out run.json
    PYTHONPATH=./stub python3 markov_baselines.py
    PYTHONPATH=./stub python3 markov_deepdive.py

Ключи стенда: `--window` (200), `--reps` (плацебо внутри выборки, 300, одни и те же перемешивания для обоих
модулей), `--wf-reps` (плацебо walk-forward, 20), `--coins` (семян монетки, 100), `--symbols BTC,ETH`,
`--check-combos` (сверить выбор комбинации опоры с перебором оригинала на каждом окне), `--refresh` (скачать
свечи заново), `--no-live` (не ходить в сеть за живой свечой), `--out файл.json`. Режим стопа относится к
опоре и монетке стенда; рабочая копия после правки стопа всегда считает по дню, поэтому её столбцы
сверяются с опорой только в режиме intraday. До правок столбец «исправлено» совпадает со столбцом
«как получено» до последнего знака, это базовая линия; каждая правка учёта меняет его предсказуемо, и
стенд печатает, что именно изменилось (цена пола, монетка, состояние живой свечи, walk-forward, комиссия).
Контракт функции `walk_forward()` для рабочей копии расписан в шапке стенда.

Кэш свечей, заглушка и файлы выдачи (`*.json`, `*.txt`) в репозиторий не попадают (см. `.gitignore`).
Выдача и разбор хранятся вне репозитория.
