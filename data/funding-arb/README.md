# Сырьё бота 1: ставки, открытый интерес, ценовой удар

На этих данных посчитано всё исследование фандинг-арбитража GMX V2 против Hyperliquid. Скрипты,
которые их читают, лежат в
[`botLab-desktop/scripts/funding-arb-study/`](../../botLab-desktop/scripts/funding-arb-study/);
там же индекс прогонов с результатами. В коде этот каталог называется `DATA` и приходит из
`paths.mjs`, переопределяется переменной `FA_STUDY_DATA`.

## Что внутри

| каталог | файлов | что | объём |
|---|---|---|---|
| `gmx-rate-snapshots/` | 63 | почасовые снимки ставки фандинга GMX прямо из первоисточника, год 2025-06-20..2026-06-20 | 17 МБ |
| `gmx-oi-snapshots/` | 63 | почасовой открытый интерес по сторонам и база фандинга. Из него считается разбавление входа | 13 МБ |
| `spread-cache-y2/` | 23 | второй год ставок пары (2023-09..2025-06) для проверки на другом периоде | 6.0 МБ |
| `gmx-impact/` | 1 | кривая ценового удара GMX по корзинам размера, знак сохранён | 448 КБ |
| `hl/` | 3 | проскальзывание по стакану Hyperliquid и суточные обороты по 63 именам | 372 КБ |
| `gmx-trades/` | 20 | отметки времени исполненных ордеров на самых залипающих рынках | 340 КБ |
| `snapshots/` | 5 | ёмкость на 2026-08-30: свободная ликвидность рынков GMX, открытый интерес и оборот Hyperliquid | 232 КБ |

JSON и CSV хранятся сжатыми, кроме мелких снимков ёмкости.

## Как это читают скрипты

Прямо в этом виде скрипты каталог не читают: они писались на плоские имена рабочего каталога и
на несжатые файлы. Соответствие имён такое:

| здесь | плоское имя, которое ждёт скрипт | сколько скриптов ждёт |
|---|---|---|
| `gmx-oi-snapshots/<токен>.json.gz` | `truth-a-oi2/<токен>.json` | 33 |
| `gmx-rate-snapshots/<токен>.json.gz` | `truth-a-src/<токен>.json` | 23 |
| `spread-cache-y2/<токен>.csv.gz` | `y2/<токен>.csv` | 7 |
| `gmx-impact/impact-gmx.json.gz`, `hl/*.json.gz` | `imp-raw/`, `impact-hl.json`, `vol63.json` | 12 |
| `gmx-trades/<токен>.json.gz` | `truth-a-trades/<токен>.json` | 3 |
| `snapshots/*.json` | те же имена в корне рабочего каталога | 5 |

Поэтому прогон с нуля требует сначала разложить данные обратно в плоский вид и распаковать, либо
перекачать их качающими скриптами заново. Причина, по которой так оставлено, и что из этого следует
для чисел исследования, разобраны в [README скриптов](../../botLab-desktop/scripts/funding-arb-study/README.md), раздел
«Как запускать».

## Чего здесь нет

- **Кэш почасовых ставок за первый год** (93 файла `<токен>_1750402800_1781938800.csv`,
  2025-06-20..2026-06-20, 83 МБ). Он собран сторонним проектом и живёт вне репозитория; путь
  задаётся переменной `FA_SPREAD_CACHE`.
- **Сырые выгрузки прогонов** целиком: фактически уплаченный фандинг по позициям, полная лента
  ордеров GMX, калибровочные окна. Это около 750 МБ на прогон, и оно воспроизводимо: качается
  заново теми же скриптами из публичных источников (GraphQL GMX на Arbitrum и API Hyperliquid).
  Здесь оставлено то, без чего числа исследования не пересчитать.
